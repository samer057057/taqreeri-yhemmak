# تقريري يهمك — حزمة تشغيل أولية

## ما الذي يعمل؟
- قاعدة بيانات SQL (SQLite محلياً أو PostgreSQL عند النشر).
- حساب مدير أولي، ثم إنشاء حسابات موظفين من صفحة المستخدمين.
- مخزون أجهزة مع IMEI/Serial فريدين.
- بيع يخصم الجهاز من المخزون.
- استبدال يربط جهازاً مستلماً وآخر خارجاً مع تسجيل الفرق.
- سجل عمليات وتقارير CSV.
- إشعار Discord لكل عملية.
- نقطة تقرير يومي محمية بمفتاح سري.

## تشغيل محلي
1. ثبّت Python 3.11 أو أحدث.
2. أنشئ بيئة افتراضية وثبّت المتطلبات:
   `pip install -r requirements.txt`
3. عيّن `SECRET_KEY` إلى قيمة عشوائية طويلة.
4. شغّل `python app.py`.
5. افتح `/setup` وأنشئ حساب المدير أول مرة فقط.

## النشر
المجلد يتضمن `render.yaml` كنقطة بداية للنشر على Render مع PostgreSQL.
اربط مستودع GitHub بالمشروع، ثم راجع متغيرات البيئة قبل النشر:
- `SECRET_KEY`: سر طويل عشوائي.
- `DATABASE_URL`: يملؤه Render من قاعدة البيانات.
- `DISCORD_WEBHOOK_URL`: رابط Webhook للروم المطلوب.
- `DAILY_REPORT_SECRET`: سر عشوائي لاستدعاء التقرير اليومي.

## التقرير اليومي
جدول مهمة مجدولة خارجية لاستدعاء:
`GET https://YOUR-DOMAIN/daily-report`
مع ترويسة:
`X-Report-Secret: YOUR_DAILY_REPORT_SECRET`
اجعلها مرة يومياً بعد إغلاق المحل. لا تضع السر في كود الواجهة.

## حدود هذه النسخة
هذه حزمة تشغيل أولية وليست اعتماداً محاسبياً نهائياً. قبل التشغيل التجاري الفعلي يلزم اختبار سير العمل، النسخ الاحتياطي والاستعادة، سياسة حذف/تصحيح العمليات، صلاحيات أكثر تفصيلاً، معالجة الضرائب والفواتير حسب المتطلبات المحلية، وسجل تدقيق غير قابل للتعديل. ميزة تحليل الصور والتعرف الآلي على الموديل لم تُفعّل بعد؛ يجب ربط خدمة رؤية اصطناعية ومراجعة النتائج قبل اعتماد الجرد.
